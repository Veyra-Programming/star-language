**Runtime ABI Version: 1**

## 1. Introduction

The **Star Runtime ABI (Application Binary Interface)** defines the memory layouts, execution model, type representations, calling conventions, capability-governed Foreign Function Interface (FFI), and package dependency contract for the Star ecosystem.

This specification ensures identical runtime behavior across all Star execution engines:
- **Reference Interpreter**
- **StarVM (Stack Machine Engine)**
- **Star Web/WASM Runtime (Star 0.5)**
- **Star Native LLVM Runtime (Star 0.6+)**

## 3. Value Representation & Memory Model

### 3.1 Type Tagging & Layouts
Every Star runtime value adheres to tagged union / polymorphic representation:

```text
+-------------------+-----------------------------------+
| TypeTag (1 byte)  | Payload / Object Reference (64-bit)|
+-------------------+-----------------------------------+
```

- `0x00 Null`: Absence of value.
- `0x01 Boolean`: 1-bit boolean flag (0 = false, 1 = true).
- `0x02 Integer`: 64-bit signed two's complement integer (`int64_t`).
- `0x03 Decimal`: 64-bit IEEE 754 floating-point number (`double`).
- `0x04 Text`: Length-prefixed immutable UTF-8 string buffer.
- `0x05 List`: Dynamically resizable buffer of value references.
- `0x06 Map`: Hash table mapping scalar keys to value references.
- `0x07 Function`: Callable closure holding code pointer and captured environment frame.
- `0x08 Instance`: Object pointer referencing `ClassDescriptor` and field array.

## 4. Controlled Foreign Function Interface (FFI)

### 4.1 Security & Capability Model
FFI is an **explicitly gated capability**. Star programs cannot access native code unless:
1. The project manifest permits it in `star.toml`:
   ```toml
   [permissions]
   native_ffi = true
   ```
2. The runtime capability is passed during invocation:
   ```text
   use FFI
   variable libc = FFI.load("c", capability = "native")
   ```

If native permissions are absent or execution occurs in a sandboxed target (e.g. Web), `FFI.load()` raises a `Star Runtime Error: Capability 'native_ffi' not granted`.

### 4.2 Supported Type Marshalling ABI (Version 1)
Star 0.4 strictly supports safe scalar marshalling. Raw pointer arithmetic, unchecked buffer offsets, and raw structs are disallowed:

| Star Value | Native C Type | Marshalling Direction | Constraints |
|:---|:---|:---|:---|
| `Integer` | `int64_t` | In / Out | Exact 64-bit precision |
| `Decimal` | `double` | In / Out | IEEE 754 double precision |
| `Boolean` | `bool` / `int` | In / Out | 0 = false, 1 = true |
| `Text` | `const char*` | In (to C) / Out (from C) | Null-terminated UTF-8 |

## 5. Package System & Dependency Resolution

### 5.1 Project Manifest (`star.toml`)
Defines project identity and dependency intent:
```toml
[project]
name = "my_app"
version = "0.1.0"
entry = "main.star"
description = "Star Application"

[star]
language = "0.4"
runtime_abi = 1

[permissions]
native_ffi = true

[dependencies]
math_extra = "0.2.1"
```

### 5.2 Deterministic Lockfile (`star.lock`)
Records resolved dependencies with cryptographic SHA-256 integrity checksums:
```toml
# Auto-generated by Star Package Manager. Do not edit.
lockfile_version = 1

[[package]]
name = "math_extra"
version = "0.2.1"
source = "packages/math_extra"
checksum = "sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
```

### 5.3 Distribution Archive (`.starpkg`)
A reproducible gzip tarball containing:
- `star.toml`
- `src/` (Star source files)
- `README.md` & `LICENSE`
- `metadata.json`
